# Web 高级交互设计

## 核心判断

网页从“能用”到“好用、有质感”，关键在于让用户的每次操作都有明确、及时、连续的反馈。微交互应服务于状态理解和任务完成，而不是单纯增加动画。

## 六类交互模式

| 优先级 | 模式 | 适用场景 | 关键实现 |
| --- | --- | --- | --- |
| P0 | 完成反馈按钮 | 提交、点赞、收藏、加入购物车 | 按下缩放；加载态；成功态切换为勾选或成功提示。 |
| P0 | 勾选联动 | 任务清单、筛选器、购物车 | 计数、进度、卡片样式和批量操作按钮同步更新。 |
| P1 | 叠卡展开 | FAQ、详情、规格列表 | 手风琴展开；内容渐显；其他卡片收起。 |
| P1 | 吸附卡加进度线 | 推荐流、案例、横向卡片 | `scroll-snap` 对齐；进度线反映滚动位置。 |
| P2 | 惯性滚动 | 长列表、画廊、时间轴 | 先用原生平滑滚动；确有需要再引入 Lenis 等方案。 |
| P2 | 圆形扩散转场 | 页面跳转、弹窗、主题切换 | 以点击点为圆心，用 View Transitions 或遮罩动画扩散。 |

## 落地原则

### 1. 先做状态反馈，再做视觉效果

优先实现“提交中 / 成功 / 失败 / 可继续操作”等状态。按钮动画应该帮助用户确认操作结果，不能只做装饰。

### 2. 一个状态变化至少影响两个相关位置

例如勾选任务后，同时更新卡片视觉、顶部计数和进度条；但联动数量不宜过多，避免页面产生噪声。

### 3. 信息层级逐步展开

使用手风琴、叠卡和渐显动画控制信息密度。移动端优先保证点击区域、焦点状态和关闭路径清晰。

### 4. 动画要有降级方案

为 `prefers-reduced-motion` 提供静态或缩短动画的方案；滚动库、View Transitions 和复杂遮罩需在目标浏览器中验证。

### 5. 以组件化复用

React/Vue 项目可封装为按钮状态组件、联动列表、手风琴、横向卡片和转场组件；纯静态站用 CSS 加少量原生 JavaScript 即可实现前四类。

## 推荐实施顺序

1. 完成反馈按钮。
2. 勾选联动和表单校验。
3. 叠卡展开。
4. 横向卡片吸附与进度指示。
5. 根据页面定位决定是否加入惯性滚动和转场。

## 代码提示

```css
.btn {
  transition: transform 0.15s cubic-bezier(0.34, 1.56, 0.64, 1),
              background-color 0.25s ease;
}

.btn:active {
  transform: scale(0.95);
}
```

```css
.scroll-container {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-behavior: smooth;
  gap: 16px;
}

.snap-card {
  flex: 0 0 280px;
  scroll-snap-align: center;
}
```
